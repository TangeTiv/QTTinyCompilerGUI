# TINY 编译器设计与实现 — 实验报告

## 一、实验目的

1. 深入理解编译原理中词法分析、语法分析、语义分析和代码生成各阶段的工作原理与实现方法。
2. 掌握递归下降分析法（Recursive Descent Parsing）的设计思路，能够根据 BNF 文法手动构造语法分析器。
3. 掌握确定性有限自动机（DFA）在词法分析中的应用，能够设计状态转移图并实现词法分析程序。
4. 学会使用哈希表实现符号表，完成变量的存储管理与类型检查。
5. 理解目标代码生成的流程，掌握基于栈式虚拟机的指令发射与地址回填技术。
6. 培养将编译原理理论与工程实践相结合的能力，通过 Qt 框架构建完整的编译器图形界面。

## 二、实验内容

本实验设计并实现了一个面向 **TINY 扩展语言** 的完整编译器。该编译器以 TINY 语言源代码（`.tny` 文件）作为输入，依次经过词法分析、语法分析、语义分析三个阶段，最终生成可在 TM（Tiny Machine）虚拟机上执行的汇编代码。

编译器整体采用 **C++17** 语言编写，基于 **Qt 6.9.1** 框架构建图形用户界面。在标准 TINY 编译器的基础上，本实验扩展了以下语言特性：

- 扩展比较运算符：`<=`（小于等于）、`>=`（大于等于）、`<>`（不等于）
- 扩展算术运算符：`%`（取模）、`^`（幂运算）
- 自增自减运算符：`++`（自增）、`--`（自减）
- 循环结构：`while-endwhile` 循环、`for` 循环
- 正则表达式赋值：`::=` 运算符及 `|`、`&`、`#`、`?` 正则操作符
- 图形化语法树展示与错误信息实时反馈

## 三、实验文档

### 3.1 系统总体结构

编译器的整体架构遵循经典的**三段式编译模型**，如下图所示：

```
┌─────────────┐    Token流    ┌─────────────┐    语法树    ┌─────────────┐    TM代码    ┌──────────────┐
│  词法分析器  │ ──────────→  │  语法分析器  │ ──────────→  │  语义分析器  │ ──────────→  │  代码生成器  │
│  (Scanner)   │              │  (Parser)    │              │  (Analyzer)  │              │  (CGen)      │
└─────────────┘              └─────────────┘              └─────────────┘              └──────────────┘
       ↑                            ↑                            ↑                            ↑
       │                            │                            │                            │
  字符序列                      Token序列                    语法树节点                   指令序列
```

各阶段的核心功能如下：

| 阶段 | 输入 | 输出 | 核心数据结构 | 关键技术 |
|------|------|------|-------------|----------|
| 词法分析 | 源代码字符序列 | Token 流 | 行缓冲区 + DFA状态机 | 有限自动机、超前读取与回退 |
| 语法分析 | Token 流 | 语法树（AST）| TreeNode 多叉树 | 递归下降分析法 |
| 语义分析 | 语法树 | 注释语法树 | 哈希符号表 | 前序/后序遍历、类型检查 |
| 代码生成 | 注释语法树 | TM 汇编代码 | 代码缓冲区 | 地址回填、栈式求值 |

### 3.2 数据结构设计

#### 3.2.1 词法单元类型（TokenType）

编译器定义了统一的词法单元枚举类型 `TokenType`，涵盖 TINY 扩展语言的所有语法要素：

```
TokenType 枚举（共 35 种词法单元）：
├── 簿记用（2种）: ENDFILE, ERROR
├── 保留字（11种）: IF, THEN, ELSE, END, REPEAT, UNTIL, READ, WRITE,
│                   WHILE, ENDWHILE, FOR
├── 多字符词法单元（2种）: ID（标识符）, NUM（数字常量）
├── 基本运算符（17种）:
│   ├── 赋值: ASSIGN(:=), REGEX_ASSIGN(::=)
│   ├── 算术: PLUS, MINUS, TIMES, OVER, MOD, POWER, INC, DEC
│   ├── 比较: EQ, LT, LE, GT, GE, NEQ
│   └── 正则: OR(|), AND(&), CLOSURE(#), OPTIONAL(?)
└── 分隔符（3种）: LPAREN, RPAREN, SEMI
```

#### 3.2.2 语法树节点（TreeNode）

语法树采用**多叉树结构**，每个节点 `TreeNode` 包含以下字段：

- **子节点数组** `child[4]`：最多 4 个子节点指针，分别对应不同语法结构的分支（如 IF 语句的条件、THEN 分支、ELSE 分支各占一个子节点）
- **兄弟节点指针** `sibling`：指向同一层级的下一语句或表达式，用于将多个顺序语句链接成链表
- **节点类型标识** `nodekind`：区分语句节点（StmtK）和表达式节点（ExpK）
- **子类型联合体** `kind`：根据节点种类选择 `stmt` 或 `exp` 子类型
- **属性联合体** `attr`：存储节点的具体属性，如运算符类型（op）、常量值（val）、变量名（name）
- **类型字段** `type`：记录表达式求值类型（Void / Integer / Boolean），用于类型检查

这种设计将语法树的节点类型收敛到单一结构体中，通过联合体节约内存，同时保持了类型安全性。以 IF 语句为例，其树形结构如下：

```
           IfK (child[0] = 条件, child[1] = then分支, child[2] = else分支)
          /    |    \
   条件表达式  then序列  else序列(可选)
```

#### 3.2.3 符号表（Symbol Table）

符号表采用**哈希表 + 分离链接法**实现：

- **哈希表大小**：211（质数，减少哈希冲突）
- **哈希函数**：对字符串每个字符，左移 4 位后累加取模
- **桶节点**：每个 `BucketListRec` 存储变量名、内存位置、行号链表和指向下一个节点的指针
- **行号链表**：每个 `LineListRec` 记录变量出现的源代码行号，便于调试和错误报告

#### 3.2.4 TM 代码生成机制

代码生成工具维护两个关键位置指针：

- `emitLoc`：当前指令发射位置（即将写入的地址）
- `highEmitLoc`：已发射的最高地址

通过这对指针配合 `emitSkip()`、`emitBackup()`、`emitRestore()` 三个函数，实现了**地址回填（backpatching）**机制，这是处理条件跳转和目标地址不确定场景的核心技术。

### 3.3 关键算法设计

#### 3.3.1 词法分析 — 基于 DFA 的状态机

词法分析器采用**确定性有限自动机（DFA）**作为识别引擎。状态机包含以下 11 个状态：

| 状态 | 含义 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| START | 起始状态 | 初始/上一个 Token 识别完毕 | 读入任何有效字符的首字符 |
| INNUM | 识别数字 | 遇到数字字符 `[0-9]` | 遇到非数字字符 |
| INID | 识别标识符 | 遇到字母 `[a-zA-Z]` | 遇到非字母字符 |
| INASSIGN | 识别赋值 | 遇到 `:` | 读入 `=` 或第二个 `:` |
| INREXASS | 识别正则赋值 | 在 INASSIGN 中再次遇到 `:` | 读入 `=` |
| INPLUS | 识别加号/自增 | 遇到 `+` | 读入 `+` 或其他字符 |
| INMINUS | 识别减号/自减 | 遇到 `-` | 读入 `-` 或其他字符 |
| INLT | 识别小于系列 | 遇到 `<` | 读入 `=`、`>` 或其他字符 |
| INGT | 识别大于系列 | 遇到 `>` | 读入 `=` 或其他字符 |
| INCOMMENT | 注释状态 | 遇到 `{` | 遇到 `}` 回到 START |
| DONE | 完成状态 | 任何状态确定 Token 边界 | 返回 TokenType |

状态转换的核心逻辑如下：

```
START ──数字──→ INNUM ──非数字──→ DONE
START ──字母──→ INID  ──非字母──→ DONE（查保留字表）
START ── ':' ─→ INASSIGN ── '=' ──→ DONE (:=)
                         ── ':' ──→ INREXASS ── '=' ──→ DONE (::=)
START ── '+' ─→ INPLUS ── '+' ──→ DONE (++)
                         ──其他──→ DONE (+)
START ── '<' ─→ INLT ── '=' ──→ DONE (<=)
                        ── '>' ──→ DONE (<>)
                        ──其他──→ DONE (<)
START ── '{' ─→ INCOMMENT ── '}' ──→ START
                               EOF ──→ DONE (ENDFILE)
START ── '(',')',';','*','/','%','^','|','&','#','?' ──→ DONE
```

**行缓冲机制**：扫描器按行读取源文件到 `lineBuf` 缓冲区，`getNextChar()` 从缓冲区中逐个返回字符，`ungetNextChar()` 支持回退一个字符。这种设计将文件 I/O 与字符处理解耦，同时简化了多行注释和跨行 Token 的处理。

#### 3.3.2 语法分析 — 递归下降法

语法分析器采用**递归下降分析法（Recursive Descent Parsing）**，为 TINY 扩展语言的每个非终结符编写一个递归函数。TINY 语言的完整 BNF 文法定义如下：

```
program        → stmt_sequence
stmt_sequence  → statement { ";" statement }
statement      → if_stmt | repeat_stmt | assign_stmt | read_stmt
               | write_stmt | while_stmt | for_stmt
if_stmt        → IF exp THEN stmt_sequence [ ELSE stmt_sequence ] END
repeat_stmt    → REPEAT stmt_sequence UNTIL exp
while_stmt     → WHILE exp stmt_sequence ENDWHILE
for_stmt       → FOR ( assign_stmt ; exp ; assign_stmt ) stmt_sequence
assign_stmt    → ID ( ":=" exp | "::=" regexexp )
read_stmt      → READ ID
write_stmt     → WRITE exp
exp            → simple_exp [ ("<" | "=" | "<=" | ">" | ">=" | "<>") simple_exp ]
simple_exp     → term { ("+" | "-") term }
term           → power { ("*" | "/" | "%") power }
power          → factor { "^" factor }
factor         → NUM | ID | "++" ID | "--" ID | "(" exp ")"
regexexp       → regex_term { "|" regex_term }
regex_term     → regex_factor { "&" regex_factor }
regex_factor   → regex_atom { "#" | "?" }
regex_atom     → NUM | ID | "(" regexexp ")"
```

##### 递归下降函数调用栈示例（以 `if a > 0 then write 1 end` 为例）

```
parse()
  └── stmt_sequence()
       └── statement()          → token = IF
            └── if_stmt()
                 ├── match(IF)           ← 消耗 IF
                 ├── exp()               ← 分析条件表达式
                 │    └── simple_exp()
                 │         └── term()
                 │              └── power()
                 │                   └── factor()  → token = ID "a"
                 │                        └── ...
                 │              └── ... 遇到比较运算符
                 │                   └── OpK(<)
                 │                        ├── IdK(a)
                 │                        └── ConstK(0)
                 ├── match(THEN)
                 ├── stmt_sequence()
                 │    └── statement()   → token = WRITE
                 │         └── write_stmt()
                 │              ├── match(WRITE)
                 │              └── exp() → ConstK(1)
                 ├── match(END)
                 └── return IfK节点
```

**关键设计要点**：

- `match()` 函数是递归下降分析的基本操作：若当前 Token 匹配预期类型则消费并读取下一个，否则报告语法错误。
- 语句节点通过 `sibling` 指针链接成链表，用于表示顺序执行的语句序列。
- 算数运算符采用**左结合**处理方式——在 `simple_exp` 和 `term` 中，遇到运算符时构建新的 OpK 节点，将已构建的表达式作为左子节点，继续解析右操作数。
- 幂运算符 `^` 在单独的 `power()` 函数中处理，保证其优先级高于乘除。

#### 3.3.3 语义分析 — 遍历与类型检查

语义分析分为两个子阶段：

**阶段一：构建符号表（前序遍历）**

采用前序遍历（Preorder Traversal）语法树，在访问到 AssignK、ReadK 和 IdK 节点时，将涉及的标识符插入符号表。如果变量首次出现，分配一个新的内存位置；如果已存在，只添加行号引用。

遍历顺序：`当前节点 → child[0] → child[1] → ... → sibling`

**阶段二：类型检查（后序遍历）**

采用后序遍历（Postorder Traversal）语法树，先确定子节点的类型，再检查父节点。这样可以保证在检查父节点时，所有子节点的类型都已确定。

遍历顺序：`child[0] → child[1] → ... → 当前节点 → sibling`

类型检查规则：

| 节点类型 | 检查规则 | 结果类型 |
|---------|---------|---------|
| ConstK | 无条件通过 | Integer |
| IdK | 无条件通过 | Integer |
| OpK（算术） | 左右操作数必须为 Integer | Integer |
| OpK（比较） | 左右操作数必须为 Integer | Boolean |
| IfK | 条件表达式不能为 Integer | — |
| AssignK | 右侧表达式必须为 Integer | — |
| WriteK | 表达式必须为 Integer | — |
| RepeatK | 循环条件不能为 Integer | — |

#### 3.3.4 代码生成 — TM 虚拟机汇编

代码生成器遍历语法树，为目标机 TM 生成汇编指令。TM 虚拟机有 8 个寄存器：

| 寄存器 | 编号 | 用途 |
|--------|------|------|
| ac | 0 | 累加器（主运算寄存器） |
| ac1 | 1 | 辅助累加器 |
| gp | 5 | 全局指针（全局变量基址） |
| mp | 6 | 内存指针（临时区栈顶） |
| pc | 7 | 程序计数器 |

**表达式求值（栈式）**：二元运算表达式采用"左操作数压栈 → 右操作数求值 → 出栈运算"的策略。例如 `a + b` 生成以下指令序列：

```
LD  ac, 0(gp)       ; 加载 a 到累加器
ST  ac, 0(mp)       ; a 压栈
LD  ac, 1(gp)       ; 加载 b 到累加器
LD  ac1, -1(mp)     ; a 出栈到 ac1
ADD ac, ac1, ac     ; ac1 + ac → ac
```

**IF 语句（地址回填）**：条件跳转地址在翻译时未知，先生成一个占位跳转指令并记录位置，待确定目标地址后回填。以 IF 语句为例：

```
    ; 条件表达式代码 (结果在 ac 中)
    JEQ  ac, ?(pc)   ; 条件为假跳转到 else（地址待回填）
    ; THEN 分支代码
    LDA  pc, ?(pc)   ; 跳转到 end（地址待回填）
    ; ELSE 分支代码
    ; end:
```

问号处即为需要回填的地址，通过 `emitSkip()` → `emitBackup()` → `emitRestore()` 三个函数协作完成。

## 四、实验总结

### 4.1 遇到的问题与解决方法

**问题一：词法分析中 ++/-- 与 +/- 的歧义处理**。在状态机设计中，`+` 和 `-` 字符可能表示二元运算符，也可能是自增自减的前缀。解决方案是在 INPLUS 和 INMINUS 状态中采用超前读取一个字符的方式：如果下一个字符也是相同的符号，则识别为 INC 或 DEC；否则回退并识别为 PLUS 或 MINUS。

**问题二：地址回填的时空一致性**。在 IF 语句的代码生成中，条件跳转的目标地址在翻译 THEN 分支时才能确定。通过 `emitSkip` 预留指令槽，`emitBackup` 回退填入地址，`emitRestore` 恢复正常发射位置的组合机制，优雅地解决了这一问题。

**问题三：GUI 与编译器后端的集成**。编译器后端采用标准 C++ 文件流进行 I/O，而 GUI 基于 Qt 框架。通过在 `main.cpp` 中声明全局文件流指针，GUI 中将用户输入的代码写入临时文件再传递给编译器后端，实现了两个模块的解耦。

### 4.2 心得体会

通过本次实验，我深入理解了编译器的各个阶段是如何协同工作的。词法分析器将字符流抽象为 Token 流，语法分析器将 Token 流组织成具有层次结构的语法树，语义分析器赋予语法树以语义信息，最终代码生成器将高层次的结构转化为低层次的机器指令。这一层层抽象与转换的过程，正是计算机科学中"分而治之"思想的经典体现。

递归下降分析法虽然手工编码量较大，但其代码结构与文法规则一一对应的特性使得调试和维护变得直观。DFA 状态机的设计让我体会到了有限自动机在模式识别中的强大能力——一个仅含 11 个状态的自动机就能完整识别拥有 35 种 Token 类型的语言。

此外，通过 Qt 框架为编译器构建图形界面，让原本"黑箱"的编译过程变得可视化。语法树的树形控件展示帮助直观理解代码的层次结构，错误信息的实时反馈也有助于快速定位语法问题。

### 4.3 不足与改进方向

1. 代码生成部分对部分扩展特性（如 `for` 循环、`^` 运算符）的翻译尚未完全实现。
2. 错误恢复机制较为简单，遇到第一个语法错误即停止分析，未能实现 panic-mode 恢复。
3. 符号表暂不支持嵌套作用域，所有变量位于同一全局作用域。
